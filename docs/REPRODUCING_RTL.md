# Reproducing actual RTL execution

`scripts/reproduce.py` checks the released feature-level evidence without EDA
tools. This document describes the separate execution path used to generate
such observations.

## Dependencies

- Python 3.10 or newer, standard library only;
- GCC or Clang with C11 and `__int128` support;
- Yosys to elaborate the RTL and regenerate the bit-level OIM;
- a separately obtained WPI source tree matching `provenance/rtl_sources.json`.

The archived interface toolchain was Python 3.12.14, GCC 15.2.0, and Yosys 0.66.
The runtime uses `__int128`; use GCC/Clang rather than MSVC. Linux/WSL or an
appropriate MinGW environment can execute these commands. Build products and
generated observations go under `build/`, which is ignored by Git.

On Windows, select one complete GCC installation rather than mixing its
executable and DLLs with another installation. In PowerShell, replace the
example path with your own compiler:

```powershell
$env:CC = 'C:\toolchains\gcc\bin\gcc.exe'
$env:Path = (Split-Path $env:CC) + ';' + $env:Path
python scripts/reproduce.py --check-core
```

Both Python scripts honor `CC` (or an explicit `--cc`) and prepend that
compiler's `bin` directory to the compiler subprocess PATH. The PowerShell
PATH setting also applies when running generated executables manually. These
settings affect the current shell and its child processes; no system-wide
PATH change is required. `gcc --version` alone does not verify that `cc1.exe`
and its runtime DLLs can compile a program.

Obtain the WPI reference from:
https://github.com/Secure-Embedded-Systems/open-source-reference-for-reproducible-side-channel-assessment-of-Post-Quantum-Standards

Use the root containing `rtl/obi/` and `rtl/ise/`. The upstream archive records
base commit `46dbacf0975c85877db49885c2f13a8bb7767297` and local edits. The build
script verifies normalized-text file hashes before applying the included
patches, so a different snapshot fails explicitly rather than silently testing
a different DUT. Normalizing CRLF to LF does not change these text hashes.

## Standalone masked modules

Run from the repository root, replacing `/path/to/wpi-reference`:

```bash
python scripts/build_rtl.py --case sec_and --upstream /path/to/wpi-reference
cd build/sec_and
./driver 10 --campaign-seed 0
```

On Windows the executable is `driver.exe`; run `./driver.exe` from PowerShell.
The script prints the appropriate command for the current operating system.
Ten samples per class is a functional/numerical smoke test, not the paper's
5,000-trace screening campaign. For that campaign use 2,500 samples per class.

Available cases and full-run arguments:

| Build case | Purpose | Run arguments after `driver` |
|---|---|---|
| `sec_and` | Output HW/CP and four-bank pipeline HD | `2500 --campaign-seed 0` |
| `sec_add` | Adder output HW/CP, with first-order paired checking | `2500 0` |
| `sec_add_entries` | Zero-inclusive FSM HD and five-entry profiles | `2500 0` |
| `a2b` | A2B output HW/CP, with first-order paired checking | `2500 0` |
| `a2b_entries` | A2B boundary snapshots for post-run diagnosis | `2500 0` |

Replace seed 0 with 1 and 2 in separate run directories to preserve each
campaign's files. Driver output filenames are fixed. To evaluate the adder's
other fixed operands, rebuild the entry driver with:

```bash
python scripts/build_rtl.py --case sec_add_entries --condition zero --upstream /path/to/wpi-reference
python scripts/build_rtl.py --case sec_add_entries --condition mixed --upstream /path/to/wpi-reference
```

These build into `build/sec_add_entries_zero` and `build/sec_add_entries_mixed`.
The mixed operands are `0x0A53` and `0x136C`. All-ones is the default condition.
The standalone drivers' `--m3-only` mode retains in-loop output statistics and
omits the trace-wise output branch. Retained FSM-entry records used for the
paper's internal diagnosis are generated in full/paired runs.

## Matched interface intervention

Build both variants:

```bash
python scripts/build_rtl.py --case interface_baseline --upstream /path/to/wpi-reference
python scripts/build_rtl.py --case interface_split --upstream /path/to/wpi-reference
```

Run `driver 10 0` in each printed build directory for a smoke test, or
`driver 2500 0` for a paper-size seed-0 campaign. Repeat seeds 1 and 2 separately.
The same driver supplies matched operands, masks, PRNG words, and protocol.
It writes `trace_audit.csv`, `statistics.csv`, and `return_bus_cycles.csv`.
The split path is generated by `patches/split_return_storage.patch`.

Use the reset-per-trace protocol when comparing with the released bank-write
results. Each bank then writes from zero to its share. Match inputs, returned
shares, cycle counts, and protocol hashes across variants before comparing
statistics. Reassess both bank writes and returned-share observations; the
shared-register overwrite, adjacent-cycle bus HD, and valid-endpoint HD have
different meanings.

## PQC drivers

`drivers/cbd2_driver.cpp` and `drivers/ntt_driver.c` preserve the actual archived
execution-integrated drivers. This compact release provides their paired
per-event statistics and configured coverage. Their frozen generated models
and NTT input/event pools are not included in the compact build entry point.

When integrating these drivers with independently regenerated models, check
the runtime-to-RTL mapping first: CBD2's archived model uses `RESULT_DFF=14`,
and NTT's uses `oim_dffs[3]` for the 32-bit `result_reg`. A newly generated OIM
can assign different indices. Preserve the original identity or resolve the
register by name before executing. CBD2 generates its coefficient inputs in
the driver; NTT requires its matching `inputs.hex`, event schedule, and expected
outputs. The command-line formats are documented at the start of each driver.

## Build recipes and scope

The per-design recipes are intentionally separate. The interface recipe skips
`proc_rom` so instruction decoding stays explicit mux logic for this generator.
The adder/A2B adaptations expose the exact diagnostic registers, and the A2B
adaptation supplies external randomness. Replacing these recipes with one
generic Yosys flow can change the model and observation identities.

Output HW/CP and interface tests reduce during execution. The reported FSM HD
diagnosis uses retained per-trace records for post-run analysis. HW/HD are RTL
activity proxies; physical characterization requires higher-fidelity modeling
or measurements.
